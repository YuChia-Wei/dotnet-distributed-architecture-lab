## Plan And Apply Behavior

The exact v0.7.0 inventory produced `67` operations: `24` safe operations
(`19` additions and `5` replacements) and `43` explicit reconciliations. The
first apply attempt inside the sandbox wrote a prefix of the safe operations and
then failed with `Permission denied` at
`.codex/agents/context-translator.toml`. It produced no receipt and did not roll
back its earlier writes. Those exact writes were restored, the clean starting
commit `9586f862f30f6ba38c824e3d53899804ba56a9a0` was read back, and the identical
apply command was rerun outside the sandbox. That attempt applied all `24` safe
operations, preserved all `43` reconciliation paths, and produced the retained
pending-validation receipt.

This is an upstream feedback case: package application is not transactional
before receipt creation. A late permission failure can leave an unreceipted
partial mutation which the caller must detect and restore.
