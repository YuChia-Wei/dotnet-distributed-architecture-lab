## Initialization experiment

The installed instruction-only skill is used through its `initialize` operation;
there is no initialization CLI. Product background already exists in README and
the authoritative requirements. Existing AGENTS and target policies already
provide the collaboration baseline. They are reused rather than duplicated into
new seed-named documents.

The identified missing foundation is a general first-task guide. It supplies a
read-only Inventory reservation example and a bounded documentation-navigation
example tied to existing target files. Authoring those prompts does not execute
either task. New navigation links those project facts and rules to the actual
installed routes. Root facts and Traditional Chinese parity are reconciled while
existing product/engineering decisions remain in place.

The first authoring pass changed eleven context files: the English/Traditional
Chinese AGENTS pair, eight navigation entries and the new first-task guide.
A separate repeated `initialize` gap review found that the three responsibilities
were covered without adding product-context or collaboration-baseline duplicates.
It found one remaining stale navigation description in each root README; both
were corrected from RC4 to stable 0.19.0 and init 0.2.0, with all other README
lines preserved. Readback confirmed the correction, all eighteen registry
versions matched their installed metadata, and no further authored file was
needed. This is a read-only semantic gap review, not proof of automatic native
skill discovery or deterministic execution idempotence.

The bounded link, structured-data, LF, placeholder, managed-hash and diff checks
passed. Independent bilingual review found no actionable mismatch in the AGENTS
pair. Comparison with the 1,533-file starting snapshot confirmed that all 1,093
tracked files outside the selected change scope remained byte-identical. The
architecture, project inventory, adopted rule authority, custom roles and prior
record directories were unchanged. See the [validation record](evidence/validation.json)
