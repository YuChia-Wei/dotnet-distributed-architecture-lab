# UI and adapter implementation contract

created_at: 2026-09-26T06:15:44+00:00; updated_at: 2026-09-26T06:15:44+00:00

Version1; source requirements AC01–06 and main8213a9e controller/source discovery. Expected behavior; not test results.

## Shared frontend behavior

Relative same-origin fetch only (`/api/...`), never hardcode 8180–8185 in browser data calls. JSON Content-Type for mutation, no success assumption from 2xx without expected body. Handle empty 204, JSON ProblemDetails (`message`, `detail`, `title`, `code`), plain-text errors, malformed response and transport failure. Bound/friendly user error, no stack trace rendering. Preserve original input after failure. GET refresh explicit, ignore/cancel stale requests; each action owns a busy flag. No automatic POST/PATCH/DELETE retry. UUID generation crypto.randomUUID with localhost secure-context availability; nonempty UUID checks. Quantity/stock require integer in int32 range; money finite nonnegative <=2 decimals. Form button doubleclick cannot send concurrent mutation. Browser storage is optional preferences/local recent IDs only, never presented as server-owned customer history.

## Customer pages

Routes `/web/`, `/web/products/:id`, `/web/orders/:id?`; nav 商品 / 訂單查詢 / 管理後台. Catalog uses GET /api/products -> array `{id,name,description,price}`; client-side text search and actual result count; no fake pagination/category/availability. Product detail GET /api/products/{id}; choose single product quantity, unit/total display from received snapshot. Products API GET missing may return generic failure; render friendly error, not made-up 404.

POST /api/orders body `{operationId:uuid,orderDate:ISO UTC,totalAmount:price*quantity,productId,productName,quantity}`. Existing server trusts these snapshots; preserve its contract, do not claim server-authoritative checkout or new price validation. Success shape `{isSuccess:true,value:{orderId},errorMessage:null}`; 400 plain string may mean insufficient inventory. Display success only for valid isSuccess and orderId, then query detail. An ambiguous transport/5xx/malformed response must show uncertain result and retain operationId, disable blind re-submit; explicit new attempt is a deliberate action with warning. This is client accidental-duplicate prevention, not a new server exactly-once guarantee. Do not automatically resubmit existing operationId.

GET /api/orders/{id} -> `{orderId,lineItems:[{productId,quantity}]}`. Render exactly available line items; optional product-name lookup has independent error and falls back to ID. No fabricated state, payment, shipment, total/date from detail. Optional local recent IDs clearly labeled 此瀏覽器的最近訂單. No customer cancel/ship/deliver or list-all endpoint.

## Admin navigation and domain pages

Routes `/admin/` overview (real service probe status / shortcuts, no fake KPI), `/admin/products`, `/admin/inventory`, `/admin/procurement`, `/admin/procurement/:id`, `/admin/integrations`.

Products: GET /api/products; POST body `{name,description,price}` returns200 product; PUT /{id} same body returns200 empty; DELETE /{id} returns200 empty. Required nonblank name, price guard; explicit delete confirmation. Refresh list only after successful mutation. Product selector reused within the app for Inventory and Procurement.

Inventory: GET `/api/inventory/product/{productId}` -> `{productId,availableQuantity}`. No list exists: choose product then load. POST same path initialize, POST suffix `/increase`, `/decrease`, `/restock`, all body `{stock:int}`. Distinguish initial/absolute restock from increment/decrement using actual source semantics, verify labels before implementation. Missing GET may be500; show unavailable/retry rather than assume stock0 or automatically initialize. Explicit operator must choose initialize. Successful writes refresh actual server stock.

Procurement: provider exact direct|wiremock|microcks; GET `/api/procurement/suppliers/{provider}/catalog/{sku}` -> `{sku,name,unitPrice,currency,origin}`. SKU ASCII `[A-Za-z0-9_-]{1,64}`; known examples REAL-001, MOCK-001, DENY-001. GET `/api/procurement/purchase-orders` newest max100 array; clearly 最近100筆, no fabricated total/paging. POST body `{clientRequestId,productId,supplierSku,quantity,unitPrice,currency:'TWD',provider}`; retain frozen request identity once sent, including across uncertain outcome. A new purchase is explicit new UUID/new draft; do not change provider or money on an existing identity.

Purchase response `{id,identity:{clientRequestId,productId,supplierSku,quantity,unitPrice,currency,provider},state,supplierOrderId,receivedQuantity,version,createdAt,updatedAt,receipts:[{receiptId,purchaseOrderId,productId,quantity,receivedAt}]}`. 201 new,200 replay,202 pending/unknown are all valid responses; show state truthfully. States PendingSubmission,SubmissionUnknown,Accepted,Rejected,PartiallyReceived,Received. GET /{id}; POST /{id}/reconcile no body, 202 still uncertain else200. Reconcile visible for pending/unknown, no auto-purchase retry. Receipt POST /{id}/receipts `{receiptId,quantity}` -> `{order,receipt,created}` 201/200. Only Accepted/PartiallyReceived enable receipt, qty <= ordered-received. Preserve receipt UUID+qty for retry after ambiguous outcome; read back order receipts to reconcile before re-post. No assumption that supplier acceptance adds Inventory; physical receipt does. Show source/provider and received/remaining counts, history, timestamps; success feedback distinct from queued/in-doubt.

## Integrated developer controls

WireMock browser base `/api/admin/supplier-mock`; GET `/control/state` -> `{mode,status,upstream,persistence}`; POST `/control/mode` `{mode}`, POST `/control/reset`, GET `/control/mappings`, GET `/control/requests`, DELETE `/control/requests`. Raw mappings/requests displayed as escaped readable JSON with count if schema supports, never HTML. Controls report applying/failed/ready; switch/reset may clear logs, require explicit confirmation. Refresh reads actual state, not assumed local selection.

Microcks via same base: GET `/control/microcks/state`; POST `/control/microcks/mode` `{mode:'mock'|'proxy'|'hybrid'}`. Proposed response `{mode:string|null,status:'ready'|'unconfigured'|'custom'|'applying'|'failed'|'unavailable',serviceId:string|null,serviceName:'Supplier API',serviceVersion:'1.0.0',operations:[{name,method,dispatcher,dispatcherRules}],message:string|null}`. Agent may add fields but keep these agreed fields. Read current native service metadata and derive mode by complete known dispatcher/rules fingerprint; mode null for absent/custom/unavailable, never cached selection as truth. POST imports only bundled preset as filename supplier-api.yaml through `/api/artifact/upload?mainArtifact=true`, validates upload result and reads native service back. Fixed configured Microcks origin only; no arbitrary URL/file/script inputs. Serialize mutation; bad enum400 without I/O; unavailable502/503; surface failure truthfully and allow explicit retry. Set applying state coherently; operation completion independent of disconnected UI request within bounded timeout. Keep native dispatchers/proxy semantics; no homemade mock engine. Include testable HTTP adapter and focused tests for bad mode, upstream failure, custom/unconfigured recognition and stable filename/readback.

Sandbox base `/api/admin/supplier-sandbox`: GET `/sandbox/orders`, GET `/sandbox/requests`, GET/PUT `/sandbox/control` `{delayAfterCommitMs:0..10000}`. Show real recent records; set delay explicit, default unchanged. UI explains delayed response after supplier commit, and mock match miss fallback differs from upstream error fallback. Microcks fallback only imported operations; WireMock native matching can proxy broader paths. Existing full fixed POST fixture remains unchanged. Native Microcks advanced UI stays documented at localhost8184; integrated daily controls all use same YARP origin.

## Build and routing

Each app includes package-lock.json, scripts dev/build/typecheck/test and README. Use Node22 compatible selected versions, prefer Docker Node22 >=22.12 for build; verify local runtime requirements (host22.14 may require newer Node for newest tools). Nginx production image stable version, not dev server. build base and router history `/web/` or `/admin/`; dist copied into Nginx `/usr/share/nginx/html/web` or `/admin`. Preserve prefix through YARP. Nginx redirects bare prefix, `try_files` index for SPA paths, missing asset404, default outside prefix404. Tests for URI/API/error/identity semantics and meaningful form behavior, not just implementation snapshots. No Docker deployment by implementation workers; parent performs actual integration.
